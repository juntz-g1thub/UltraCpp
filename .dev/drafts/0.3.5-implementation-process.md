## §1. 用户决策一览（7 项硬约束）

0.3.5 启动前，orchestrator 与用户对齐 7 项决策（全部已"按推荐执行"批准）：

### D1 — CJK 标识符永久 NO-OP（user 确认 2026-08-21）
**决定**：CJK 标识符永久不进任何版本（不进 0.3.5、不进 0.4.0、永远）。
**理由**：language design 决策——lexer / parser / symbol table 不引入非 ASCII 路径；避免双语 spec 中 zh-CN / en 版本标识符语义差异；周边工具链（debugger / IDE / formatter）零负担。
**影响**：spec §2.4 显式 ASCII-only 明文（0.3.5 spec 第一组变更）；spec gap **§S7** 状态从 `deferred` 改为 **`❌ Permanently NO-OP`**；m0_50 已通过 runner marker 机制 PASS（per commit `02d7170`），无需 src-c 改动。

### D2 — 不动 0.3.4 spec（immutable 原则）
**决定**：0.3.4 spec 双语文件（`docs/UltraCPP-v0.3.4-spec-{zh-CN,en}.md`）**不可修改**；0.3.5 spec 第一组变更通过新写 `docs/UltraCPP-v0.3.5-spec-{zh-CN,en}.md` 完成。
**理由**：已发布 spec 不可回改；保持历史 spec 完整性以供回溯。
**影响**：0.3.5 spec 与 0.3.4 spec 并存，0.3.5 spec §0 metadata 标注 `supersedes 0.3.4`。

### D3 — lib/uc_runtime.c 仍不创建（0.3.4 决策延续）
**决定**：0.3.5 不创建 `lib/uc_runtime.c`（C bootstrap 临时 builtin 文件）。
**理由**：runtime 仍走 lib/*.uc UltraCPP 自实现路径（per 0.3.4 D1 + runtime-architecture §9 Stage 1）。
**影响**：`lib/uc_runtime.c` 在 git history 中**永不出现**；src-c/Makefile 不编译 lib/*.uc。

### D4 — M1 词法扩展范围（per milestones §3.1）
**决定**：0.3.5 M1 词法扩展 = `mod/unmod`（0.3.3 已实施 lexer）+ `shared / __thread / move_to_thread / typedef`（4 个新 keyword token）+ compound_assign（5 个运算符 token）。
**理由**：M1 是 borrow-check 前置（M2-M5 推 0.4.0+）；mod/unmod 不重复实施；compound_assign 是 §S7 之外的 m0_07 必翻点。
**影响**：commit 14e（keyword lexer）+ commit 14f（compound_assign）；m0_07 翻 PASS（per §5.2）。

### D5 — 多 agent 分组并行
**决定**：0.3.5 阶段用多类 agent 并行推进：
- **Group L（spec，1 agent）**：14a-errata 串行
- **Group P（parser/codegen，1 agent 串行）**：14b → 14c → 14d 顺序（共享 ast.h enum）
- **Group K（lexer，1 agent 串行）**：14e → 14f 顺序（共享 uc_token.h）
- **Group C（cleanup，1 agent）**：14g
- **Group D（docs sync，1 agent）**：commit 15 phase 1-6
**理由**：parser/codegen / lexer 各自有共享头文件依赖；cleanup 独立；docs 是收尾。

### D6 — commit 排序
**决定**：spec first → parser/codegen → lib/*.uc → cleanup → docs。
**理由**：spec 先行（per AGENTS.md "spec 先于代码"）；codegen 串行；cleanup 独立（14g 在 14f 之后，无依赖）；docs 最后（commit 15）。
**影响**：与 0.3.4 plan 一致。

### D7 — lib/*.uc stdlib 测试基础设施纳入 0.3.5（推翻原 plan §5.4）
**决定**：commit 14g' 新增 test/programs/lib_unit/ + test/e2e/run_lib_tests.sh。
**理由**：用户指令（2026-08-21）：所有 0.3.4 标 stub 须在 0.3.5 测通；测试基础设施对齐 commit 14 链（14g cleanup + 14h print_float 完整化 + 既有 10a-10e lib/*.uc）。
**影响**：原 plan §5.4 "lib/*.uc bootstrap 测试推 0.3.5+" 决策修正为"0.3.5 启用"。

> **实际执行（per §4 deviation）**：commit 14g' + commit 14h + commit 14i **未在 0.3.5 实施末态 `fe649be` 中落地**。原因：lib/*.uc 测试基础设施与 arm64 syscall 实现的优先级在 0.3.5 链中未触及（per `.dev/drafts/0.3.0-post-0.3.3-plan.md` 后续排序）。这两项**明确推迟到 0.3.6**（per §7 范围外）。该 deviation 不影响 0.3.5 实施完成度（m0 baseline 36/49 + C unit 554/554 目标达成）。

## §11. Errata（0.3.6 启动前校正）

> 本节为 0.3.6 启动前对 0.3.5 文档的事实校正记录。0.3.5 plan / process 按 immutable 原则保留（不再修订），仅以本 errata 标记认知偏差。

### §11.1 commit 14g' / 14h / 14i 推迟到 0.3.6

原 plan `.dev/drafts/0.3.5-implementation-plan.md` §3 假设 11 个 src/lib commits + 1 docs commit（commit 15）共 12 commits；实际仅落地 9 个 src/lib commits + 6 docs commits = **15 commits**。

**差异**：commit 14g'（lib/*.uc test infra per D7）+ commit 14h（print_float ftoa）+ commit 14i（arm64 sys raw）**未在 0.3.5 链中落地**，deferred to 0.3.6。

**影响**：
- 0.3.5 末态 `lib/print.uc::uc_print_float` 仍为 STUB（写 `<float>` 字符串）
- `lib/sys/raw.uc` 仍为 x86_64 only
- lib/*.uc stdlib 测试基础设施（test/programs/lib_unit/）未启用

**结论**：0.3.5 实施完成度评估应以本 errata §11.1 为准——9 src/lib commits + 6 docs commits = 15 commits；lib/*.uc 完整性提升推到 0.3.6。

### §11.2 m0_38 typedef 未在 0.3.5 翻 PASS

commit 14e lexer 集成 `typedef` keyword token + parser 路径，但 m0_38 实际**未翻 PASS**（per §5.2 实际）。原因：typedef 类型系统的 codegen 路径未完整（仅 lexer + parser 集成，缺 codegen emit_type_def 等）。

**建议**：0.3.6 实施时补 m0_38 翻 PASS 路径（per §7 范围外 + 0.3.6 plan 起草时）。本 errata 标记 0.3.5 14e commit 的 m0 baseline 影响边界。

### §11.3 lib/io.uc 处置说明

lib/io.uc 在 0.3.5 spec §11.0.2 标 deprecate，但 0.3.5 实施**未删除** lib/io.uc（与 commit 14b-14g 实施边界无重叠）。**lib/io.uc 删除 = 0.3.6 commit**（per §7 范围外 + spec §11.0.2 deprecation 过渡）。
