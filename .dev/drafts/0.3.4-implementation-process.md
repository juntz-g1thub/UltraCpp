## §1. 用户决策一览（6 项硬约束）

0.3.4 启动前，orchestrator 与用户对齐 6 项决策（全部已"按推荐执行"批准）：

### D1 — UltraCPP 直接 bootstrap lib/*.uc（**不创建 `lib/uc_runtime.c`**）
**决定**：不创建 `lib/uc_runtime.c`（C bootstrap 14 项 builtin 临时文件）。
**理由**：runtime-architecture §9 Stage 1 直接用 `uc_compiler` 编译 `lib/*.uc`（UltraCPP 自实现 stdlib），不走 C 临时 bootstrap。当前 src-c/ 已采用 inline LLVM IR + libc 链接混合方案（per 0.3.3 process §2.1），临时 C bootstrap 已被证明不必要的假设（per 0.3.3 process §2.5）。
**影响**：`lib/uc_runtime.c` 在 git history 中**永不出现**；src-c/Makefile 不编译 lib/*.uc；lib/*.uc 用 `uc_compiler --build` 编译为 `libuc.a`（远期 0.4.0+ Stage 1 启动）。

### D2 — `abs_int` 完全从 BUILTIN_SIGS[] + `get_builtins_defs` 移除
**决定**：`abs_int` 从 `BUILTIN_SIGS[]`（`src-c/src/codegen.c:38` 当前第 1 项）完全删除；同时从 `get_builtins_defs()` 中删除 `@builtin_abs_int` inline IR 实现（21 行，per 0.3.3 process §2.1）。
**理由**：abs_int 行为简单（`abs(n) = n < 0 ? -n : n`），完全可以由 UltraCPP 自身实现（`lib/math.uc::uc_abs`）；保留 inline IR 等于把 stdlib 函数"植入"编译器，违背 runtime-architecture §3.1 "UltraCPP 不使用 libc 作为 runtime" 原则。
**影响**：codegen 新增 `emit_uc_abs_call` 路由函数（约 30 LOC）；`UCExprCall` 主流水中**新增分支**（`fn_name == "uc_abs"` → `emit_uc_abs_call`）；m0_41 测试链改为 `abs_int(-7)` → ... → `@uc_abs`（lib/math.uc 中定义）。
**回归保证**：lib/math.uc::uc_abs 行为必须与原 inline IR **完全一致**（per R2 风险缓解）。

### D3 — P3 spec gaps 范围 = S6 + S8 + S9（不推 S1/S2）
**决定**：0.3.4 spec 修订仅解决 `.dev/drafts/0.3.0-m0-priority.md` §9.x 中的 **S6**（FFI extern body 来源）+ **S8**（deref-assign 类型安全）+ **S9**（main 返回 N 实际行为 / exit code 8-bit 截断）。
**理由**：S1（`*` `&` `mod` `unmod` 一元优先级）已在 0.3.1 解决；S2（lvalue/rvalue 概念缺失）已在 0.3.3 解决；S4（C-style cast）已在 0.3.2 解决。S6/S8/S9 是 M0 baseline 中**最后 3 个未明 spec 缺口**，必须随 m0_41/m0_42/m0_30/m0_34/m0_36/m0_48 修复一并解决才能翻 PASS。
**影响**：spec 修订规模从 S1-S9 全集（250-350 LOC）缩小到 S6/S8/S9 三个缺口（80-150 LOC）；codegen 修订范围对应缩减（30-50 LOC）。

### D4 — `lib/sync.uc`（mutex/atomic）推到 0.3.5 / M5
**决定**：0.3.4 不写 `lib/sync.uc`（mutex/atomic 包装）。
**理由**：M5（线程模型）是独立里程碑（per `.dev/plans/0.3.0-borrow-check-milestones.md` §3.5），启动条件是 `shared` / `__thread` / `move_to_thread` 关键字全部 lexer/parser/codegen 完成（M1 范畴），0.3.4 阶段这些关键字尚未就绪。
**影响**：lib/ 目录在 0.3.4 阶段只增 5 个文件（print.uc + string.uc + memory.uc + math.uc + alloc.uc + sys/sys.uc + sys/raw.uc = 7 个），不增 `lib/sync.uc`；m5_t5/m5_t6 测试（M5 mutex/atomic 范畴）**不在 0.3.4 目标 baseline 范围**。

### D5 — P4（P3-5 pointer runtime）纳入 0.3.4 commit 11c（**实际 skipped**）
**原决定**：`m0_41` / `m0_42` / `m0_30` / `m0_34` / `m0_36` 修复（deref-assign LHS 类型 + abs_int linker + call signature + pointer runtime）作为 commit **11c**，纳入 0.3.4。
**实际执行**：commit 11c **skipped**（per §2 架构发现）；原 plan 假设的 `m0_30/34/36/42` 4 个测试卡在 deref-assign LHS 类型修复，**早由 0.3.3 commit 6 (88dfae4) 实质修复**（emit_move_call/clone_call/alloc_call/free_call + 6 builtin entries）。
**影响**：commit 11c 不再需要，baseline 32/48 维持不变（m0_30/34/36/42 早 PASS）。

### D6 — 多 agent 分组并行（lib/*.uc 5 文件并行 + codegen 串行 + docs 1 agent）
**决定**：0.3.4 阶段用 3 类 agent 并行推进：
- **Group L（lib/*.uc，5 个并行 agent）**：10a / 10b / 10c / 10d / 10e 独立 commit，可同 session 内并行 dispatch
- **Group C（codegen，串行 3 agent）**：11a → 11b → 11c 顺序执行（前 commit 是后 commit 的依赖）
- **Group D（cleanup + docs，1 agent）**：12 → 13 合并到 1 个 agent 串行
**理由**：lib/*.uc 文件之间无依赖（每个文件都是独立 UltraCPP 源码模块）；codegen 修改之间有依赖（11a 依赖 10d 完成 lib/math.uc 存在，11c 依赖 11b spec 定型）；cleanup + docs 是收尾工作，不影响中间 commits。
**影响**：orchestrator 在 lib/*.uc 全部完成后停下验证 baseline + 决定是否进入 codegen 阶段（关键 checkpoint）；codegen 11a 后单独验证 m0_41 仍 PASS（abs_int 走新路径）；11c 后单独验证 m0_30/34/36/42 翻 PASS（实际 skipped，per D5）。
