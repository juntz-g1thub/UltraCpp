## 3. 已识别未起草(S6/S7/S8/S9)

### 3.1 S6:FFI extern 函数 body 来源策略(§10 缺)

| 字段 | 内容 |
|------|------|
| **spec 章节** | §10.1-§10.3 |
| **缺陷** | spec 没定义 `extern "C" { ... }` 块内的函数 body 从哪来 — libc 链接?编译器 stub?测试 stub 文件? |
| **当前 workaround** | m0_41(abs_int)用 expects_compiler_error 机制,实际 link 失败 |
| **根因** | spec §10 缺"extern 函数 body 来源"明确策略 |
| **修复方案(草)** | 0.3.2+ 加 §10.5"FFI 函数体来源"章节,定义 3 种策略:libc 链接 / 编译器 stub / 测试 stub 文件;src-c 实现对应查表机制 |
| **影响范围** | m0_41 abs_int 链接失败(P0-2 已 work around);任何 extern 块内的非 libc 函数都会卡住 |
| **紧迫度** | **中** |
| **预计版本** | 0.3.2+ 或 0.4.0 |
| **状态** | 未起草 |

### 3.2 S7:CJK 标识符支持(§2.4 明确**禁止**,**用户已确认**)

| 字段 | 内容 |
|------|------|
| **spec 章节** | §2.4 标识符规则 |
| **缺陷** | spec §2.4 明确:`identifier ::= letter (letter | digit)*`,`letter ::= 'a'..'z' | 'A'..'Z' | '_'` —— **CJK 字符不在 letter 集合中** |
| **spec 立场** | **标识符不应当支持 CJK**(与 C/C++/Rust 一致) |
| **当前 workaround** | m0_50_chinese_identifiers.uc 用 expects_compiler_error 标记,baseline 跑出 PASS(因为测试目标 = 编译器正确拒绝) |
| **用户决定(本会话)** | **保持 spec §2.4 禁止 CJK**,不实现 CJK 支持,**推到 0.4.0+** 重大 spec 修订 |
| **修复方案** | 0.3.x 不动 spec;若 0.4.0+ 决定加 CJK,需 §2.4 letter 集合扩 + lexer UTF-8 支持 + codegen 标识符映射(高风险,破坏 ABI) |
| **影响范围** | 仅 m0_50(已用 workaround 解决,无实际 bug) |
| **紧迫度** | **低**(0.4.0+ deferred) |
| **预计版本** | 0.4.0+(若决定加)|
| **状态** | **明确 deferred,不再处理** |
| **备注** | ⭐ 用户已明确表态:**spec 不支持 CJK**,此 spec gap 不修复,保留 spec §2.4 禁止 |

### 3.3 S8:deref-assign 类型安全剩余(§4.6/§4.1)

| 字段 | 内容 |
|------|------|
| **spec 章节** | §4.6 赋值,§4.1 优先级 |
| **缺陷** | spec 缺 lvalue/rvalue 概念定义,导致 `*p = v` 中 `*p` 是 lvalue 还是 rvalue 边界不明;S2 修大部分但剩余 LHS 类型安全未完全处理 |

| **修复方案** | 0.3.3+ 加 §4.6.1 详细 lvalue 上下文中 `*p` 行为(emit GEP 而非 load);codegen 改 `UCExprAssign` LHS codegen 路径 |
| **影响范围** | m0_30(deref 已在 P3-5)等;未来 deref-assign 模式 |
| **紧迫度** | **低**(0.3.2 partial 修复,大部分场景覆盖) |
| **预计版本** | 0.3.3+ 或 0.4.0 |
| **状态** | 未起草 |

### 3.4 S9:exit code 8-bit 限制(§9.8 未明说)

| 字段 | 内容 |
|------|------|
| **spec 章节** | §9.8 编译流程 |
| **缺陷** | spec §9.8 列 5 阶段编译流程(源码→IR→llc→obj→link→exe)但没说"exit code 8-bit 限制" — shell `$?` 只存 0-255,>255 截断 |
| **当前 workaround** | m0_19 factorial(6) = 720 > 255,实际返回 208(720 mod 256)用 trailing `// 208` 注释让 runner 识别 |
| **根因** | spec §9.8 缺 §9.8.1"测试与运行时差异"小节 |
| **修复方案** | 0.3.2+ 加 §9.8.1,说明 exit code 8-bit 限制 + 测试文件 trailing comment 约定;或 src-c 加 exit code 64-bit 支持 |
| **影响范围** | 任何返回 >255 的整数测试;P2/P3 涉及 |
| **紧迫度** | **低**(已 workaround) |
| **预计版本** | 0.3.2+ 或 0.4.0 |
| **状态** | 未起草 |
