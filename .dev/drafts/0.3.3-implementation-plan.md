## 2. Executive Summary

0.3.3 (minor) 是 **spec 清晰化 (clarification)**, **不是 bug fix, 不是 breaking change**。

- **0.3.3 (minor) 而不是 0.4.0 (major)** 的理由:
  - 不引入新语法, 不破现有 27 PASS 程序
  - 把 `mod` `unmod` `move` `clone` 从"运算符"分类改为"builtin 函数"分类, 调用语法不变 (`mod(ref)` 仍是函数调用形式)
  - 引入 §7.0 概念清晰化 (运算符 vs builtin 函数)
  - 引入 §4.13.5 deref 语义边界 (4 种 deref 形式完整化)
  - §11.0 重新分组为 §11.0.1 (语言原语 7 项) + §11.0.2 (stdlib 14 项)
  - codegen 补 2 个 builtin (`move` / `clone`) 完整 emit + BUILTIN_SIGS[] 7 项简化 (~90 LOC), 让 m0_36 翻 PASS
  - **不补** `mod` / `unmod` emit — 它们是**编译期决策**, 无 runtime 函数

- **影响**:
  - **2 个新章节** §7.0 (概念清晰化) + §4.13.5 (deref 语义)
  - **1 个新章节分类** §11.0.1 (语言原语) + §11.0.2 (stdlib 约定) — 替代 0.3.2 单表
  - **5 个现有 spec 章节修订** §4.1 + §4.9/§4.10 + §7.8 + §12.1 + §12.3
  - **0 个新语法** (0.3.3 不引入)
  - **0 个 bug fix** (0.3.3 不修 bug)
  - **27/48 baseline PASS 测试预期全保留** + m0_36 翻 PASS = **28/48 PASS**
  - **505/505 单元测试预期全保留**

## 3. 问题描述

### 3.1 spec 内部矛盾 (§4.1 vs §4.9/§4.10)

**矛盾点 1**: §4.1 表第 15 级列 `move clone` 为"运算符", 但 §7.4 描述 `move(p)` 是"**内建 primitive, 不是语法糖, 也不是普通函数**"。

**矛盾点 2**: §4.1 注脚说"`mod` / `unmod` (修改权)属于一元运算符",但 §4.9 描述 `mod(ref_expr)` 为 `mod '(' reference_expression ')'` — 明显是**函数调用**语法。

**矛盾点 3**: §12.3 附录优先级表与 §4.1 主表**不一致**:
- §4.1 主表第 15 级是 `move clone`
- §12.3 附录表第 15 级是 `move clone move_to_thread` 并附"一元运算符"表 (含 `mod unmod`)

**矛盾点 4**: §12.1 EBNF 把 `move` 放在 `unary_expression` 中, 与 `*` / `&` 同级, 语义模糊。

**修复路径**:
- §4.1 表: **删除 15 级** `move clone` (它们是 builtin 函数)
- §4.1 注脚: **改写**, 说明 `mod` / `unmod` 是 builtin 函数调用
- §12.3 附录: **同步** §4.1 修订 (删 15 级 + 加 2.5 级 + 删 `mod`/`unmod` 一元表行)
- §12.1 EBNF: 加 `builtin_function_call` 产生式, `mod` / `unmod` / `move` / `clone` 移到该产生式

### 3.2 deref 语义边界模糊

**现状**: 0.3.0 / 0.3.2 spec 没有专门的 deref 语义子节。deref 散落在:
- §4.1 表 (2.5 级 `*`)
- §3.5 指针类型
- §7 指针使用

**问题**:
- `*p` (lvalue 读) vs `*p = v` (lvalue 写) 的语义边界不清晰
- `**pp` 多级 deref 没有显式说明
- `&*p` / `*&x` 恒等性没有显式说明
- `p->field` ≡ `(*p).field` 等价性没有显式说明
- `*` 在 2.5 级 (deref) vs 3 级 (乘法) 的同名异义没有显式区分

**修复路径**:
- **新增 §4.13.5 deref 语义** (6 子节):
  - §4.13.5.1 基本 deref `*p` (lvalue)
  - §4.13.5.2 复合 deref (`&*p` / `*&x` / `**pp` / `p->field`)
  - §4.13.5.3 与 §3.5 指针类型关系
  - §4.13.5.4 优先级 (2.5 级, 与 `*` 乘法同名异义)
  - §4.13.5.5 错误情况 (`InvalidDereferenceError`)
  - §4.13.5.6 交叉引用

### 3.3 §11.0 单分类 vs 双分类

**0.3.2 现状**: §11.0 单表 18 项 builtin, 混 I/O / 字符串 / 内存 / 工具 / 数学 / 语言原语。

**问题**:
- `alloc` / `free` / `move` / `clone` / `null` / `mod` / `unmod` 是**语言原语**, 与所有权/借用检查直接相关
- `print` / `strlen` / `memcpy` / `abs_int` 是 **stdlib 约定**, 与借用检查**无关**
- 两者性质不同, 应分组

**修复路径**:
- **§11.0.1 builtin 语言原语** (7 项: alloc / free / move / clone / null / mod / unmod)
- **§11.0.2 stdlib 约定** (14 项: I/O / 字符串 / 内存 / 工具 / abs_int)
- **§11.0.3 codegen 集成** (`BUILTIN_SIGS[]` 简化为 7 项, 无 `is_type_parametric` 字段)

### 3.4 codegen 缺 2 个 builtin emit (m0_36 翻 PASS)

**m0_36 测试源** (`test/programs/baseline/m0_36_move_free.uc`):

```cpp
// m0_36 actual content (from test/programs/baseline/m0_36_move_free.uc):
unique int p = alloc(int);   // unique T → owning pointer
*p = 42;
unique int q = move(p);      // 所有权转移; p moved-out
free(q);
```

**触发**: m0_36 测试同时验证 `unique T` 类型 + `move(p)` 所有权转移 + `free(q)` 释放。

**当前状态**: 0.3.2 codegen **缺** `UC_EXPR_MOVE` / `UC_EXPR_CLONE` 的完整 emit 路径 — 这 2 个 builtin 当前可能走 fallback 或硬编码 i32, 导致 m0_36 runtime_fail。

> **plan A 简化**: 0.3.3 不补 `UC_EXPR_MOD` / `UC_EXPR_UNMOD` emit — `mod` / `unmod` 是**编译期决策**, **无 runtime 函数**, **无 `UC_EXPR_MOD` / `UC_EXPR_UNMOD` AST 节点**。mod/unmod 状态由编译器在 ownership pass 中静态跟踪, 不需要在 codegen 层 emit 任何 runtime 调用。

**修复路径**:
- codegen.c 加 2 个 emit 函数 (`emit_move_call` / `emit_clone_call`)
  - `emit_move_call`: IR 标记所有权 (`@uc_own_move`) + 加载原值 + 返回新 owner
  - `emit_clone_call`: alloc(T) + LLVMBuildMemcpy + 返回新副本
- §11.0.1 BUILTIN_SIGS 数组简化为 **7 项** (alloc/free/move/clone/null/mod/unmod), 无 `is_type_parametric` 字段 (类型参数化由 `UCExprCall.return_type` 字段承担, 0.3.2 §6.2.1 已加)
- **总预估 ~90 LOC** (codegen.c)

### 3.5 §7.0 概念清晰化缺失

**现状**: spec 没有"运算符 vs builtin 函数"的概念分类章节。

**问题**:
- §4.1 优先级表 (运算符) 和 §11.0 builtin 签名表 (函数) 的关系不清晰
- `mod` / `unmod` / `move` / `clone` 历史上在两个表之间反复横跳
- spec 维护者和 implementer 都易误读

**修复路径**:
- **新增 §7.0 概念清晰化** (5 子节):
  - §7.0.1 运算符 (§4.1)
  - §7.0.2 builtin 函数 (§11.0)
  - §7.0.3 关键澄清 (mod/unmod/move/clone 函数化)
  - §7.0.4 历史回顾
  - §7.0.5 交叉引用

### Phase 4: codegen.c `UC_EXPR_MOVE` emit (1.5h)

**位置**: `src-c/src/codegen.c` 加 `UC_EXPR_MOVE` case (若不存在) 或 `emit_move_call()` 函数。

> **plan A 简化**: `move(p)` 是**真实 emit**, **不是 pass-through**。原 plan "加载 + 置 null + 返回" 是错描述 — 实际需要 IR 标记所有权转移 (源 moved-out), 然后加载值返回新 owner。

```c
case UC_EXPR_MOVE:
    // move(p) - IR 标记所有权 + 加载 + 返回
    // 1. emit @uc_own_move(p_slot, new_owner_slot) IR intrinsic
    //    (标记 p 为 moved-out; 后续对 p 的访问触发编译期错误)
    // 2. 加载 p_slot (仍是 owning 值, 但源已经 moved-out)
    // 3. 返回新 owner
    return emit_move_call(g, ptr_value, type, err);
```

- [ ] 实现 `emit_move_call()` 函数
  - IR 标记所有权 (例如 `@llvm.uc.own.move(p_slot)` intrinsic, 或在 p_slot 旁设标志位)
  - 加载 p_slot 作为新 owner 的值

### 6.4 4 个 builtin 函数 codegen emit 草案

```c
// === UC_EXPR_MOVE: move(p) — 加载 + 置 null + 返回 ===
static LLVMValueRef emit_move_call(CodeGen* g, LLVMValueRef ptr_value, Type* type, Error** err) {
    // 1. 分配临时变量保存 ptr_value
    LLVMValueRef temp = LLVMBuildAlloca(g->builder, LLVMTypeOf(ptr_value), "move_temp");
    LLVMBuildStore(g->builder, ptr_value, temp);

    // 2. 把 p_slot 写为 null (i8* null)
    LLVMValueRef null_val = LLVMConstNull(LLVMPointerType(LLVMInt8Type(), 0));
    LLVMBuildStore(g->builder, null_val, ptr_value);  // p_slot = null

    // 3. 加载临时变量返回
    return LLVMBuildLoad(g->builder, temp, "move_result");
}

// === UC_EXPR_CLONE: clone(s) — 深拷贝 ===
static LLVMValueRef emit_clone_call(CodeGen* g, LLVMValueRef src_value, Type* type, Error** err) {
    // 1. alloc(T) 给新指针
    LLVMValueRef new_ptr = emit_alloc_call(g, type, err);
    if (!new_ptr) return NULL;

    // 2. memcpy 从 src 拷贝 sizeof(T) 字节到 new_ptr
    LLVMValueRef size = LLVMSizeOf(LLVMTypeOf(src_value));  // sizeof(T)
    LLVMValueRef memcpy_ret = LLVMBuildMemcpy(g->builder, new_ptr, 0, src_value, 0, size);

    // 3. 返回 new_ptr
    return new_ptr;
}

// === UC_EXPR_CLONE: clone(s) — 深拷贝 ===
// (emit_clone_call 草案完整保留 — 实施时按需调整)
static LLVMValueRef emit_clone_call(CodeGen* g, LLVMValueRef src_value, Type* type, Error** err) {
    // 1. alloc(T) 给新指针
    LLVMValueRef new_ptr = emit_alloc_call(g, type, err);
    if (!new_ptr) return NULL;

    // 2. memcpy 从 src 拷贝 sizeof(T) 字节到 new_ptr
    LLVMValueRef size = LLVMSizeOf(LLVMTypeOf(src_value));  // sizeof(T)
    LLVMValueRef memcpy_ret = LLVMBuildMemcpy(g->builder, new_ptr, 0, src_value, 0, size);

    // 3. 返回 new_ptr
    return new_ptr;
}

// === mod(ref) / unmod(ref) — 编译期决策, 无 emit 函数 ===
// plan A 简化: mod/unmod 是 **编译期决策**, 编译器在 ownership pass 中
// 静态跟踪 mod 状态 (§7.1 + Rule 24), **不需要** codegen 层 emit。
// 没有 emit_mod_call / emit_unmod_call 函数, 也没有 @uc_runtime_mod_fn /
// @uc_runtime_unmod_fn runtime 调用。
```

**说明**:
- `emit_move_call` / `emit_clone_call` 是核心, m0_36 翻 PASS 关键

## 10. 风险评估

| 风险 | 等级 | 缓解 |
|---|---|---|
| codegen.c 缺 `UC_EXPR_MOVE` 节点, 需要从 AST 节点层扩展 | **中** | 先 git grep `UC_EXPR_MOVE` 确认; 若不存在, 需加 AST 节点 (5-10 LOC) |

| `mod(ref)` / `unmod(ref)` 误实现为 runtime emit | **中** | plan A 明确: mod/unmod 是**编译期决策**, ownership pass 静态跟踪 (§7.1 + Rule 24), codegen 层**不**emit runtime 调用。需 implementer 警惕不加 emit_mod_call / emit_unmod_call 函数 |
| `BUILTIN_SIGS[]` 扩展触及 m0_16/18/19/20 等已有 PASS 路径 | **中** | m0_19 factorial 单独回归 smoke; 单元测试 `codegen_call*` |

| §4.13.5 deref 语义新增可能与 §3.5 指针类型重复 | **低** | §4.13.5 是语义, §3.5 是类型; 互不重叠 |

| 0.3.3 vs 0.3.2 版本号决定 | 0 | 已定 (用户选 0.3.3) |
| m0_36 测试源不明确 (`move(p) / free(p)` 形态) | **中** | 先 read 测试源确认; 若测试源不全, 需 implementer 调整 emit 适配测试 |
