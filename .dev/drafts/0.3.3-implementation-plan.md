## 2. Executive Summary

0.3.3 (minor) 是 **spec 清晰化 (clarification)**, **不是 bug fix, 不是 breaking change**。

- **0.3.3 (minor) 而不是 0.4.0 (major)** 的理由:
  - 不引入新语法, 不破现有 27 PASS 程序
  - 把 `mod` `unmod` `move` `clone` 从"运算符"分类改为"builtin 函数"分类, 调用语法不变 (`mod(ref)` 仍是函数调用形式)
  - 引入 §7.0 概念清晰化 (运算符 vs builtin 函数)
  - 引入 §4.13.5 deref 语义边界 (4 种 deref 形式完整化)
  - §11.0 重新分组为 §11.0.1 (语言原语 **6 项**, per runtime-architecture §5.1) + §11.0.2 (UltraCPP stdlib 路径 `lib/*.uc`)
  - **集成 runtime-architecture 决策** (`.dev/drafts/0.3.0-runtime-architecture.md`):
    - `free` 从 FFI 提升为 builtin (per runtime-architecture §3.2 + §5.1)
    - `mod` / `unmod` 从 intrinsic 提升为 builtin (per runtime-architecture §3.2 + §5.1)
    - `null` 退入 intrinsic (per runtime-architecture §5.2)
    - 14 项 stdlib 全部删除, 改 UltraCPP 自带 stdlib (`lib/*.uc`)
  - codegen 补 6 个 builtin emit (`alloc` / `free` / `move` / `clone` / `mod` / `unmod`) + 4 个 intrinsic codegen + 1 asm translator + 1 preprocessor (~150-200 LOC), 让 m0_36 翻 PASS
  - 新增 §10.2 预编译宏 + §10.3 内联汇编 + §10.4 `sys::` namespace (per runtime-architecture §6-§8)

- **影响**:
  - **2 个新章节** §7.0 (概念清晰化) + §4.13.5 (deref 语义)
  - **3 个新章节子节** §10.2 (预编译宏) + §10.3 (内联汇编) + §10.4 (sys::) — per runtime-architecture

## 3. 问题描述

### 3.1 spec 内部矛盾 (§4.1 vs §4.9/§4.10)

**矛盾点 1**: §4.1 表第 15 级列 `move clone` 为"运算符", 但 §7.4 描述 `move(p)` 是"**内建 primitive, 不是语法糖, 也不是普通函数**"。

**矛盾点 2**: §4.1 注脚说"`mod` / `unmod` (修改权)属于一元运算符",但 §4.9 描述 `mod(ref_expr)` 为 `mod '(' reference_expression ')'` — 明显是**函数调用**语法。

**矛盾点 3**: §12.3 附录优先级表与 §4.1 主表**不一致**:
- §4.1 主表第 15 级是 `move clone`
- §12.3 附录表第 15 级是 `move clone move_to_thread` 并附"一元运算符"表 (含 `mod unmod`)

**矛盾点 4**: §12.1 EBNF 把 `move` 放在 `unary_expression` 中, 与 `*` / `&` 同级, 语义模糊。

**修复路径**:
- §4.1 表: **删除 15 级** `move clone` (它们是 builtin 函数)
- §4.1 注脚: **改写**, 说明 `mod` / `unmod` 是 builtin 函数调用
- §12.3 附录: **同步** §4.1 修订 (删 15 级 + 加 2.5 级 + 删 `mod`/`unmod` 一元表行)
- §12.1 EBNF: 加 `builtin_function_call` 产生式, `mod` / `unmod` / `move` / `clone` 移到该产生式

### 3.2 deref 语义边界模糊

**现状**: 0.3.0 / 0.3.2 spec 没有专门的 deref 语义子节。deref 散落在:
- §4.1 表 (2.5 级 `*`)
- §3.5 指针类型
- §7 指针使用

**问题**:
- `*p` (lvalue 读) vs `*p = v` (lvalue 写) 的语义边界不清晰
- `**pp` 多级 deref 没有显式说明
- `&*p` / `*&x` 恒等性没有显式说明
- `p->field` ≡ `(*p).field` 等价性没有显式说明
- `*` 在 2.5 级 (deref) vs 3 级 (乘法) 的同名异义没有显式区分

**修复路径**:
- **新增 §4.13.5 deref 语义** (6 子节):
  - §4.13.5.1 基本 deref `*p` (lvalue)
  - §4.13.5.2 复合 deref (`&*p` / `*&x` / `**pp` / `p->field`)
  - §4.13.5.3 与 §3.5 指针类型关系
  - §4.13.5.4 优先级 (2.5 级, 与 `*` 乘法同名异义)
  - §4.13.5.5 错误情况 (`InvalidDereferenceError`)
  - §4.13.5.6 交叉引用

### 3.3 §11.0 单分类 vs 双分类

**0.3.2 现状**: §11.0 单表 18 项 builtin, 混 I/O / 字符串 / 内存 / 工具 / 数学 / 语言原语。

**问题**:
- `alloc` / `free` / `move` / `clone` / `null` / `mod` / `unmod` 是**语言原语**, 与所有权/借用检查直接相关
- `print` / `strlen` / `memcpy` / `abs_int` 是 **stdlib 约定**, 与借用检查**无关**
- 两者性质不同, 应分组

**修复路径** (per `0.3.0-runtime-architecture.md` §5.1):
- **§11.0.1 builtin 语言原语** (**6 项**: alloc / free / move / clone / mod / unmod) — `null` 退入 intrinsic (per runtime-architecture §5.2)
- **§11.0.2 UltraCPP stdlib 路径** (删 14 项, 改 `lib/print.uc` / `lib/string.uc` / `lib/memory.uc` / `lib/math.uc` 等; per runtime-architecture §3.1 + §9.2)
- **§11.0.3 codegen 集成** (`BUILTIN_SIGS[]` 简化为 **6 项**, 无 `is_type_parametric` 字段)

### 3.4 codegen 缺 2 个 builtin emit (m0_36 翻 PASS)

**m0_36 测试源** (`test/programs/baseline/m0_36_move_free.uc`):

```cpp
// m0_36 actual content (from test/programs/baseline/m0_36_move_free.uc):
unique int p = alloc(int);   // unique T → owning pointer
*p = 42;
unique int q = move(p);      // 所有权转移; p moved-out
free(q);
```

**触发**: m0_36 测试同时验证 `unique T` 类型 + `move(p)` 所有权转移 + `free(q)` 释放。

**当前状态**: 0.3.2 codegen **缺** `UC_EXPR_MOVE` / `UC_EXPR_CLONE` 的完整 emit 路径 — 这 2 个 builtin 当前可能走 fallback 或硬编码 i32, 导致 m0_36 runtime_fail。

> **plan A 修订 + runtime-architecture 集成** (per `0.3.0-runtime-architecture.md` §3.2 + §5.1):
> 0.3.3 (原 plan A) **不补** `UC_EXPR_MOD` / `UC_EXPR_UNMOD` emit — 该计划已被 runtime-architecture 决策覆盖:
> - **`mod` / `unmod` 提升为 builtin** (A 类) — 现在需要在 codegen 层 emit IR marker (`@uc_borrow_mod_enter` / `@uc_borrow_mod_exit`), 借用检查器状态入口/出口必须由 compiler 显式记录
> - **`free` 也提升为 builtin** (A 类) — 之前是 FFI (`extern "C" free`), 现在需要在 codegen 层 emit `call void @free(i8* %p)` + 标记 p 为 freed
> - mod/unmod 状态由 codegen (IR marker) + borrow checker 同步维护, 不再是单独的 ownership pass 静态跟踪

**修复路径** (per runtime-architecture §5.1):
- codegen.c 加 **6 个** emit 函数 (覆盖 §11.0.1 全部 6 项 builtin):
  - `emit_alloc_call`: `call i8* @malloc(sizeof(T))` + 类型标记 + ownership tracking
  - `emit_free_call`: `call void @free(i8* %p)` + 标记 p 为 freed (NEW, 从 FFI 提升)
  - `emit_move_call`: IR 标记所有权 (`@uc_own_move`) + 加载原值 + 返回新 owner
  - `emit_clone_call`: alloc(T) + LLVMBuildMemcpy + 返回新副本
  - `emit_mod_enter`: emit `call void @uc_borrow_mod_enter(%ref)` IR marker (NEW, 从 intrinsic 提升)
  - `emit_unmod_exit`: emit `call void @uc_borrow_mod_exit(%ref)` IR marker (NEW, 从 intrinsic 提升)
- §11.0.1 BUILTIN_SIGS 数组简化为 **6 项** (alloc / free / move / clone / mod / unmod), 无 `is_type_parametric` 字段 (类型参数化由 `UCExprCall.return_type` 字段承担, 0.3.2 §6.2.1 已加)
- `null` / `is_null` / `sizeof` / `alignof` 退入 intrinsic (per runtime-architecture §5.2), codegen 特殊处理, 不进 BUILTIN_SIGS[]
- **总预估 ~120-150 LOC** (codegen.c)

### 3.5 §7.0 概念清晰化缺失

**现状**: spec 没有"运算符 vs builtin 函数"的概念分类章节。

**问题**:
- §4.1 优先级表 (运算符) 和 §11.0 builtin 签名表 (函数) 的关系不清晰
- `mod` / `unmod` / `move` / `clone` 历史上在两个表之间反复横跳
- spec 维护者和 implementer 都易误读

**修复路径**:
- **新增 §7.0 概念清晰化** (5 子节):
  - §7.0.1 运算符 (§4.1)
  - §7.0.2 builtin 函数 (§11.0)
  - §7.0.3 关键澄清 (mod/unmod/move/clone 函数化)
  - §7.0.4 历史回顾
  - §7.0.5 交叉引用

## 4. 现有 spec 章节交互分析

### 4.1 §4.1 vs §4.9 / §4.10 / §7.4 / §7.5 — 矛盾点详细分析

| spec 章节 | 0.3.2 描述 | 0.3.3 关系 | 净效果 |

### 4.3 与 §7.1 所有权 + §7.10 自定义指针 的关系

**§7.1 所有权** (0.3.0 重写):

**结论**: **与 §7.1 / §7.10 无冲突**, 0.3.3 是 §7.1 builtin 概念的清晰化。

### 4.4 与 §6.2.1 函数返回类型 (0.3.2) 的关系

**§6.2.1** (0.3.2 新增):
- 函数调用返回类型由签名表 (builtin) 或函数定义 (用户/extern) 决定

**与 0.3.3 关系**:

**结论**: **与 §6.2.1 协同**, 0.3.3 双分类不破 §6.2.1 优先级。

### 6.4 6 个 builtin 函数 + 4 个 intrinsic + 1 asm translator codegen emit 草案

> **plan A 修订 + runtime-architecture 集成** (per `0.3.0-runtime-architecture.md` §5):
> - 旧 plan A 只有 `emit_move_call` / `emit_clone_call` 2 个 draft
> - 现在 (per runtime-architecture §5.1) 6 个 builtin 全部 emit + 4 个 intrinsic codegen + 1 asm translator
> - 总计 11 个 emit draft 覆盖 §11.0.1 (6 builtin) + §11.0.2 (4 intrinsic) + §10.3 (1 asm)

```c
// === 统一 builtin 路由 ===
static LLVMValueRef emit_builtin_call(CodeGen* g, UCExprCall* call, Type* type, Error** err) {
    // 查 BUILTIN_SIGS[] 按 name 分派
    if (strcmp(call->name, "alloc") == 0)   return emit_alloc_call(g, call, type, err);
    if (strcmp(call->name, "free") == 0)    return emit_free_call(g, call, type, err);
    if (strcmp(call->name, "move") == 0)    return emit_move_call(g, call, type, err);
    if (strcmp(call->name, "clone") == 0)   return emit_clone_call(g, call, type, err);
    if (strcmp(call->name, "mod") == 0)     return emit_mod_enter(g, call, type, err);
    if (strcmp(call->name, "unmod") == 0)   return emit_unmod_exit(g, call, type, err);
    return NULL;  // not a builtin
}

// === UC_EXPR_ALLOC: alloc(T) — malloc + 类型标记 ===
static LLVMValueRef emit_alloc_call(CodeGen* g, UCExprCall* call, Type* type, Error** err) {
    // 1. 计算 sizeof(T)
    LLVMTypeRef t = codegen_type(g, type);  // T
    LLVMValueRef size = LLVMSizeOf(t);

    // 2. emit call i8* @malloc(i64 %size)
    LLVMValueRef malloc_fn = LLVMGetNamedFunction(g->module, "malloc");
    LLVMValueRef raw_ptr = LLVMBuildCall(g->builder, malloc_fn, &size, 1, "alloc_raw");

    // 3. 标记 ownership (per runtime-architecture §5.1: emit IR marker)
    LLVMValueRef own_marker = LLVMGetNamedFunction(g->module, "@uc_own_alloc");
    LLVMValueRef marked = LLVMBuildCall(g->builder, own_marker, &raw_ptr, 1, "alloc_marked");

    // 4. bitcast 到 T* (owning)
    return LLVMBuildBitCast(g->builder, marked, LLVMPointerType(t, 0), "alloc_t");
}

// === UC_EXPR_FREE: free(p) — call @free + 标记 p 为 freed (NEW, per runtime-architecture §3.2) ===
static LLVMValueRef emit_free_call(CodeGen* g, UCExprCall* call, Type* type, Error** err) {
    // 1. emit call void @free(i8* %p)
    LLVMValueRef p = LLVMBuildLoad(g->builder, call->args[0], "free_p");
    LLVMValueRef i8_ptr = LLVMBuildBitCast(g->builder, p, LLVMPointerType(LLVMInt8Type(), 0), "free_p_i8");
    LLVMValueRef free_fn = LLVMGetNamedFunction(g->module, "free");
    LLVMBuildCall(g->builder, free_fn, &i8_ptr, 1, "");

    // 2. 标记 p 为 freed (per runtime-architecture §5.1: emit IR marker)
    LLVMValueRef free_marker = LLVMGetNamedFunction(g->module, "@uc_own_free");
    LLVMBuildCall(g->builder, free_marker, &i8_ptr, 1, "");
    return NULL;  // free 返回 void
}

// === UC_EXPR_MOVE: move(p) — IR 标记所有权 + 加载 + 返回新 owner ===
static LLVMValueRef emit_move_call(CodeGen* g, UCExprCall* call, Type* type, Error** err) {
    // 1. 加载 p_slot
    LLVMValueRef p = LLVMBuildLoad(g->builder, call->args[0], "move_p");

    // 2. emit @uc_own_move(p_slot) IR marker (per runtime-architecture §5.1)
    LLVMValueRef move_marker = LLVMGetNamedFunction(g->module, "@uc_own_move");
    LLVMBuildCall(g->builder, move_marker, &p, 1, "");

    // 3. 返回 p (作为新 owner)
    return p;
}

// === UC_EXPR_CLONE: clone(s) — 深拷贝 (alloc + memcpy) ===
static LLVMValueRef emit_clone_call(CodeGen* g, UCExprCall* call, Type* type, Error** err) {
    // 1. alloc(T) 给新指针 (复用 emit_alloc_call)
    LLVMValueRef new_ptr = emit_alloc_call(g, NULL, type, err);
    if (!new_ptr) return NULL;

    // 2. memcpy 从 src 拷贝 sizeof(T) 字节到 new_ptr
    LLVMValueRef src = LLVMBuildLoad(g->builder, call->args[0], "clone_src");
    LLVMValueRef size = LLVMSizeOf(LLVMTypeOf(src));  // sizeof(T)
    LLVMBuildMemcpy(g->builder, new_ptr, 0, src, 0, size);

    // 3. 返回 new_ptr (作为新 owning 副本)
    return new_ptr;
}

// === UC_EXPR_MOD: mod(ref) — emit IR marker @uc_borrow_mod_enter (NEW, per runtime-architecture §3.2) ===
static LLVMValueRef emit_mod_enter(CodeGen* g, UCExprCall* call, Type* type, Error** err) {
    // 1. 加载 ref
    LLVMValueRef ref = LLVMBuildLoad(g->builder, call->args[0], "mod_ref");

    // 2. emit @uc_borrow_mod_enter(%ref) IR marker (per runtime-architecture §5.1)
    LLVMValueRef enter_marker = LLVMGetNamedFunction(g->module, "@uc_borrow_mod_enter");
    LLVMBuildCall(g->builder, enter_marker, &ref, 1, "");

    return NULL;  // mod 返回 void
}

// === UC_EXPR_UNMOD: unmod(ref) — emit IR marker @uc_borrow_mod_exit (NEW, per runtime-architecture §3.2) ===
static LLVMValueRef emit_unmod_exit(CodeGen* g, UCExprCall* call, Type* type, Error** err) {
    // 1. 加载 ref
    LLVMValueRef ref = LLVMBuildLoad(g->builder, call->args[0], "unmod_ref");

    // 2. emit @uc_borrow_mod_exit(%ref) IR marker (per runtime-architecture §5.1)
    LLVMValueRef exit_marker = LLVMGetNamedFunction(g->module, "@uc_borrow_mod_exit");
    LLVMBuildCall(g->builder, exit_marker, &ref, 1, "");

    return NULL;  // unmod 返回 void
}

// === 4 个 intrinsic codegen (per runtime-architecture §5.2) ===
// === UC_EXPR_NULL: null — emit i8* null 常量 ===
static LLVMValueRef emit_null_intrinsic(CodeGen* g, Type* type, Error** err) {
    return LLVMConstNull(LLVMPointerType(LLVMInt8Type(), 0));
}

// === UC_EXPR_IS_NULL: is_null(p) — emit icmp eq i8* %p, null ===
static LLVMValueRef emit_is_null_intrinsic(CodeGen* g, UCExprCall* call, Type* type, Error** err) {
    LLVMValueRef p = LLVMBuildLoad(g->builder, call->args[0], "is_null_p");
    LLVMValueRef i8_ptr = LLVMBuildBitCast(g->builder, p, LLVMPointerType(LLVMInt8Type(), 0), "is_null_p_i8");
    LLVMValueRef null_val = LLVMConstNull(LLVMPointerType(LLVMInt8Type(), 0));
    return LLVMBuildICmp(g->builder, LLVMIntEQ, i8_ptr, null_val, "is_null_cmp");
}

// === UC_EXPR_SIZEOF: sizeof(T) — emit LLVMSizeOf(T) 编译期常量 ===
static LLVMValueRef emit_sizeof_intrinsic(CodeGen* g, Type* type, Error** err) {
    LLVMTypeRef t = codegen_type(g, type);  // T
    return LLVMSizeOf(t);  // i64
}

// === UC_EXPR_ALIGNOF: alignof(T) — emit LLVMAlignOf(T) 编译期常量 ===
static LLVMValueRef emit_alignof_intrinsic(CodeGen* g, Type* type, Error** err) {
    LLVMTypeRef t = codegen_type(g, type);  // T
    return LLVMAlignOf(t);  // i64
}

// === asm block translator (per runtime-architecture §8) ===
static LLVMValueRef emit_asm_block(CodeGen* g, UCASTAsmBlock* asm_block, Error** err) {
    // 1. 解析指令模板 (单个字符串)
    LLVMValueRef template_str = LLVMMDString(asm_block->template_str, strlen(asm_block->template_str));
    // 2. 解析约束 + 操作数
    LLVMValueRef constraints = LLVMMDString(asm_block->constraints, strlen(asm_block->constraints));
    // 3. 调用 LLVMInlineAsm (LLVM C API)
    // 注: 实际实现需要根据 LLVM 版本调用 LLVMInlineAsm / LLVMCreateInlineAsm 等
    // 这里仅展示 draft
    return NULL;
}
```

**说明**:
- **`emit_alloc_call` / `emit_free_call` / `emit_move_call` / `emit_clone_call`** 是 4 个核心 builtin emit, m0_36 翻 PASS 关键 (`move` / `free` / `clone` / `alloc` 完整 emit)
- **`emit_mod_enter` / `emit_unmod_exit`** (NEW, per runtime-architecture §3.2) 是 IR marker emit — 借用检查器状态入口/出口, 编译器必须在 IR 中显式记录
- **`emit_null_intrinsic` / `emit_is_null_intrinsic` / `emit_sizeof_intrinsic` / `emit_alignof_intrinsic`** (NEW, per runtime-architecture §5.2) 是 4 个 intrinsic codegen — 不进 BUILTIN_SIGS[], 直接 emit
- **`emit_asm_block`** (NEW, per runtime-architecture §8) 是内联汇编翻译 — 调用 LLVMInlineAsm
- 实际实现细节取决于现有 codegen 架构 (UC_EXPR_MOVE / UC_EXPR_ALLOC / UC_EXPR_FREE 等是否已存在)

## 10. 风险评估

| 风险 | 等级 | 缓解 |
|---|---|---|
| codegen.c 缺 `UC_EXPR_MOVE` 节点, 需要从 AST 节点层扩展 | **中** | 先 git grep `UC_EXPR_MOVE` 确认; 若不存在, 需加 AST 节点 (5-10 LOC) |
