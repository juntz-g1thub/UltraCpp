#### §3.1.3 Rationale

- **历史**：0.3.2 把 abs_int 收录 BUILTIN_SIGS[] + inline IR 是当时**最快**让 m0_41 翻 PASS 的方式（libc 临时转发）

**UCExprCall codegen 主流水 — 4 级优先级链**（per 0.3.2 §6.2.1 + 0.3.4 修订）：

```c
// 4 级优先级链（per 0.3.2 §6.2.1）
// P1: sys$* 前缀 → 直接映射 libc / sys:: (0.3.3 commit 8c)
// P2: BUILTIN_SIGS[] 查表 → 6 项语言原语 emit
// P3: lookup_extern_func(name) → extern lookup (用户 extern "C" 或 stdlib)
// P4: default → 假设返回 i32（fallback）

static LLVMValueRef gen_call(CodeGen* g, UCExprCall* call) {
    const char* fn_name = call->fn_name;

    // P1: sys$* 前缀 (libc / sys:: 转发)
    if (strncmp(fn_name, "sys$", 4) == 0) {
        return gen_syscall_call(g, call, fn_name + 4);
    }

    // P2: BUILTIN_SIGS[] 查表 — 6 项语言原语
    const BuiltinSig* sig = lookup_builtin_sig(fn_name);
    if (sig != NULL) {
        return emit_builtin_call(g, call, sig);
    }

    // P3: extern lookup — [0.3.4 commit 11a] abs_int 在此分支
    // - 用户 extern "C" { int abs_int(int x); } 声明
    // - stdlib (lib/math.uc::uc_abs) 提供 @abs_int 符号
    // - libc fallback (0.4.0+ 完全移除)
    LLVMValueRef fn = lookup_extern_func(g, fn_name);
    if (fn != NULL) {
        return emit_extern_call(g, call, fn);
    }

    // P4: default — 假设返回 i32（fallback）
    return emit_default_call(g, call, "i32");
}

### §5.1 S6: FFI extern body 来源策略

**原始讨论**（per `.dev/drafts/0.3.0-m0-priority.md` §9.x S6）：

#### §10.1.1.2 查找路径（codegen P3 extern lookup）

```c
// src-c/src/codegen.c: P3 extern lookup
static LLVMValueRef lookup_extern_func(CodeGen* g, const char* name) {
    // P1: libuc.a（UltraCPP stdlib，per §11.0.4 Stage 1）
    LLVMValueRef fn = LLVMGetNamedFunction(g->module, name);
    if (fn != NULL) return fn;  // libuc.a 提供

    // P2: 同进程用户 .uc（已经 emit 到 module）
    // (handled by LLVMGetNamedFunction above)

    // P3: libc fallback（0.3.x 阶段）
    // emit "declare external i32 @abs_int(i32)" → linker -lc 解析
    fn = LLVMAddFunction(g->module, name, ...);
    return fn;
}
```

**查找顺序总结**：
1. **libuc.a**（UltraCPP stdlib 静态库，0.3.4 commit 10a-10e 产出；0.4.0+ Stage 1 启动后生效）
2. **同模块已 emit 函数**（同一 .uc 文件内的前向声明）
3. **跨模块用户 .uc**（多文件编译时其他 .uc 文件的 emit 产物）
4. **libc**（fallback，0.3.x 阶段 `@malloc` / `@free` / `sys$*`）

#### §10.1.1.3 实现细节

- **codegen emit**：`UCExprCall.fn_name` 走 P3 时，emit `declare external <ret_type> @<name>(<arg_types>)` + `call <ret_type> @<name>(<args>)`
- **链接**：由 linker（gcc）解析符号；`-luc` 提供 libuc.a 符号，`-lc` 提供 libc 符号
- **找不到符号**：linker 报 `undefined reference to '<name>'`，编译失败

#### §10.1.1.4 示例（m0_41_extern_c.uc）

```c
// m0_41_extern_c.uc
extern "C" {
    int abs_int(int x);
}

int main() {
    return abs_int(-7);  // 期望返回 7
}
```

**编译链**：
```
UCExprCall("abs_int", [-7])
  → codegen 主流水 P3 lookup_extern_func("abs_int")
    → LLVMGetNamedFunction(module, "abs_int") == NULL（首次 emit）
    → LLVMAddFunction(module, "abs_int", i32(i32))
    → emit "declare external i32 @abs_int(i32)"
    → emit "call i32 @abs_int(i32 -7)"
  → linker: -luc -lc
    → libuc.a → lib/math.o::uc_abs 提供 @abs_int（符号 alias 或直接名）
    → libc 提供 @malloc / @free（builtin emit 用）
  → a.out 运行时: abs_int(-7) → uc_abs(-7) → 7
```

**回归保证**（per 0.3.4 plan §6 R2）：
- `uc_abs(-7) == 7` / `uc_abs(0) == 0` / `uc_abs(7) == 7` / `uc_abs(INT_MIN)` 行为对齐原 inline IR
- m0_41_extern_c 测试在 commit 11a 后仍 PASS（关键回归点）
```

### §5.2 S8: deref-assign 类型安全

**原始讨论**（per `.dev/drafts/0.3.0-m0-priority.md` §9.x S2 + S8）：

> §4.6 表达式 / 赋值: **lvalue / rvalue 概念缺失** + §4.6 + §4.1 联合: **deref-assign 类型安全**
> - 触发 bug: m0_34/36/42 deref-assign `*p = X` 在 store 阶段类型错；assignment LHS/RHS 分类不清
> - **最高优先级** — 直接阻塞 pointer runtime
> - S2（lvalue/rvalue 概念缺失）已在 0.3.3 §4.13 解决；S8 是 S2 子项，专门处理 deref-assign 类型路径

**问题描述**：

`*p = X` 中 `*p` 应是 lvalue（per §4.13.2 lvalue 类别表）；codegen `UC_EXPR_DEREF` 路径当前 emit `i32*` vs `i32` 类型不匹配：

```c
// 当前 codegen（per 0.3.4 plan §3.1 commit 11c）
static void emit_deref_store(CodeGen* g, UCExprDeref* deref, LLVMValueRef rhs) {
    LLVMValueRef ptr = gen_expr(g, deref->operand);
    // 旧：LLVMBuildStore(g->builder, rhs, ptr)  // i32 vs ptr mismatch ❌
    // 新：先 cast rhs 到指针基类型，再 store
    LLVMTypeRef base_type = LLVMGetElementType(LLVMTypeOf(ptr));
    if (base_type == LLVMInt32Type()) {
        LLVMValueRef rhs_i32 = LLVMBuildBitCast(g->builder, rhs, LLVMInt32Type(), "to_i32");
        LLVMBuildStore(g->builder, rhs_i32, ptr);  // i32 vs i32 ✅
    }
    // ... 其他类型
}
```

m0_30（`*p = 100;`）/ m0_34（`alloc + *p = X`）/ m0_36（`move + *p = X`）/ m0_42（`unsafe { *p = X; }`）都因 deref-assign 类型失败。

**修订方案**（spec 文本草稿）：

候选位置 1：**§4.13.5 末尾追加 §4.13.5.7 deref-assign 类型安全**

#### 4.13.5.7 deref-assign 类型安全 *(0.3.4 新增, per D3 + S8 关闭)*

> **[0.3.4 新增 — S8 关闭]** 本节明确 `*p = X` 中 `*p` 的 lvalue 分类与 codegen emit 类型一致性。0.3.3 §4.13 已建立 lvalue 概念；本节作为 §4.13.5 deref 语义子项，专门处理 deref-assign 类型路径。

#### §4.13.5.7.1 `*p` 的 lvalue 分类（per §4.13.5 + §4.13.2）

```cpp
T* p = alloc(T);   // p: T* (owning ptr)
*p = new_val;      // *p 是 lvalue (type T)，可赋值
```

- **类型**：`T`（p 的目标类型）
- **类别**：**lvalue**（per §4.13.2 lvalue 类别表 — deref 总是产生 lvalue）
- **赋值上下文**：`*p = X` 中 `*p` 是 lvalue，X 是 rvalue（per §4.13.3）
- **要求**：X 必须能隐式转换到 `*p` 的类型（即 X 类型必须与 T 兼容；典型 T = int 时 X 是 int）

#### §4.13.5.7.2 codegen emit 流程

`UC_EXPR_DEREF_ASSIGN` 节点（**0.3.4 commit 11b 新增**，S8 路径占位）：

```c
// src-c/src/codegen.c: 新增 UC_EXPR_DEREF_ASSIGN 节点处理
static void emit_deref_assign(CodeGen* g, UCExprDerefAssign* node) {
    // *p = X 语义:
    //   1. 计算 p 的 SSA 值 (type T*)
    //   2. 计算 X 的 SSA 值 (type T)
    //   3. emit store T X, T* p  (type 匹配)
    LLVMValueRef ptr = gen_expr(g, node->deref_expr);  // T*
    LLVMValueRef rhs = gen_expr(g, node->rhs);         // T
    // [0.3.4 commit 11c] 类型 cast fix（per R3）：
    //   - 当前 codegen UC_UN_DEREF emit "store i32 X, i8* %p"（类型不匹配）
    //   - 修复：先 cast rhs 到指针基类型，再 store
    LLVMTypeRef base_type = LLVMGetElementType(LLVMTypeOf(ptr));
    if (LLVMTypeOf(rhs) != base_type) {
        rhs = LLVMBuildBitCast(g->builder, rhs, base_type, "to_base_type");
    }
    LLVMBuildStore(g->builder, rhs, ptr);
}

// parser 解析 *p = X 时构造 UC_EXPR_DEREF_ASSIGN 节点
// (替代之前的 UC_EXPR_DEREF + UC_STMT_ASSIGN 二元组合)
```

#### §4.13.5.7.3 实现细节

- **`UC_EXPR_DEREF_ASSIGN` 节点**：commit 11b **仅占位**（AST 节点定义 + parser 构造）；commit 11c **完整 emit**（类型 cast fix + store 指令）
- **类型一致性检查**：codegen 必须保证 `*p` 的目标类型 T 与 X 的类型一致；不一致时 emit `BitCast` 转换
- **owning vs borrowed ptr**：`p` 是 owning `T*` 还是 borrowed `T*` 不影响 deref-assign 语义（都是 lvalue）；mod 检查由 Rule 24 单独保证（不在本节范围）

#### §4.13.5.7.4 错误情况

| 错误 | 错误类型 | 触发 |
|------|----------|------|
| `*p = X` 中 `*p` 不是 lvalue | `InvalidLvalueError` | e.g. `*(p+1) = X` 中 `p+1` 不是 lvalue（**待 review**，0.3.4 不解决）|
| `*p = X` 中 X 类型与 T 不兼容 | `TypeMismatchError` | e.g. `*p = "string"` 中 p 是 int*，X 是 char*（待 codegen 类型检查）|

| `*p = X` 中 p 是 moved-out | `UseAfterMoveError` | p 已 move 后 deref-assign（per Rule 22）|

### §5.3 S9: main 返回 N / exit code 8-bit 截断

**原始讨论**（per `.dev/drafts/0.3.0-m0-priority.md` §9.x S9）：

> §3.x / §6.x main 退出: **main 返回 N 时的实际行为**（bash `$?` 8-bit 截断）
> - 触发 bug: m0_19 factorial(6)=720 但 bash `$?` 只存低 8 bit → actual exit 208；m0_48 ternary exit=20 同样
> - spec 应说明「main return 数值 mod 256」或类似
> - 0.3.3 阶段走 trailing `// 208` workaround（m0_19 测试加 `// 208` 注释接受实际 exit 208）

**问题描述**：

`int main() { return 720; }` 中 720 超出 8-bit（255），bash `$?` 截断到 720 % 256 = 208。

测试预期 exit code = 208（per 720 % 256），但 runner 默认期望 0。当前 m0_19（factorial）测试 exit code = 720 % 256 = 208（per 6! = 720），测试用 trailing `// 208` 接受实际值。

**修订方案**（spec 文本草稿）：

候选位置 1：**§11.x 测试约定末尾追加 §11.x.x exit code 语义**
候选位置 2：**独立 §S9 章节**
候选位置 3：**§6.2 函数返回类型末尾追加 §6.2.x**

**推荐位置**：**独立 §S9 章节**（S9 是测试约定范畴，独立章节最清晰；放在 §11.x 测试约定前后）。

```markdown
### S9 main 返回值与 exit code 8-bit 截断语义 *(0.3.4 新增, per D3 + S9 关闭)*

> **[0.3.4 新增 — S9 关闭]** 本节明确 `int main() { return N; }` 中 N 的实际行为，特别是 bash `$?` 8-bit 截断是 OS-level 行为，不是 UltraCPP 行为。

#### §S9.1 main 返回值约束

- `main` 返回 `int`（per §6.2 函数返回类型）
- `return N;` 调用 `exit(N)` 系统调用（per §10.4 sys::exit 或 libc exit）
- **8-bit 截断是 OS-level 行为**（bash `$?` 只存低 8 bit），**不是** UltraCPP 行为
- UltraCPP 编译器**不做**截断；保留完整 int 值传递给 OS

#### §S9.2 测试预期

- 跑 main 的返回值（int）**原样**传递给 OS exit
- bash `$?` 取低 8 bit（OS / shell 行为）
- 测试 runner 应读取**完整退出码**而非截断值

#### §S9.3 测试 runner 实现（per .dev/drafts/0.3.3-implementation-process.md §3.1 commit 8 + 0.3.3 process §2.4）

```bash
# 当前 runner（per 0.3.3 process §2.4）— 已支持
exit_code=$(./a.out; echo "EXIT_CODE=$?")
# EXIT_CODE 包含完整 int 值（bash 内部用 32-bit 或 64-bit 存）

# 提取 expected exit code from .uc trailing comment
expected=$(grep -oP '//\s*\K\d+' "$test_file")
# 比较
if [ "$exit_code" -eq "$expected" ]; then
    echo "PASS"
else
    echo "FAIL: expected=$expected actual=$exit_code"
fi
```

**关键**：
- runner 不做 8-bit 截断 — 直接读 `$?` 完整值
- 测试预期值由 .uc 文件 trailing `// N` 注释指定（如 m0_19 的 `// 208`）
- 若实际 exit 与预期一致（含 8-bit 截断后的值），PASS

#### §S9.4 示例

```c

int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

int main() {
    return factorial(6);  // = 720
}
// 208  // 6! = 720; bash $? = 720 % 256 = 208
```

**运行时链**：
```
factorial(6) → 720
main return 720 → exit(720)
OS exit 720 → bash $? = 720 % 256 = 208（OS 行为）
runner reads $? = 208
expected from // 208 comment = 208
PASS
```

```

**章节位置最终选择**：**独立 §S9 章节**（放在 §11.0.4 之后或 §S6 / §S8 同级"已知 spec gap"小节）
