**新增段**（在 §10.4 末尾追加，**zh-CN**）：

```markdown
> **注 1（0.3.6 新增, G1 解读B）**：`sys::` namespace 保留为 user-facing API。
> 但 `lib/` 目录下的 stdlib 实现**可直接调用 `uc_syscall(SYS_xxx, ...)` 底层 primitive**，
> **不强制**经 `sys::*` wrapper 转发。`uc_syscall` 定义在 `lib/sys/raw.uc`（含 inline asm
> `asm { "syscall" }` x86_64 / `asm { "svc #0" }` aarch64 / `asm { "ecall" }` riscv64，
> per §10.3 + §10.4.4）。
>
> **何时用 `sys::xxx` vs `uc_syscall`**（3 类场景）：
> - **用户代码**：推荐 `sys::write(fd, buf, len)` 简洁跨平台（per §10.4.2 API）
> - **stdlib 实现（`lib/*.uc`）**：可绕过 `sys::xxx` 直接 `uc_syscall(SYS_xxx, arg1, ...)`，
>   避免 wrapper 层叠 indirection；具体由 lib/ 实现者选择
> - **系统编程**（如 `uc_syscall` 自身）：必须直接 `uc_syscall`
>
> **例 1**：`lib/alloc.uc::uc_alloc` 实现（per 0.3.6 commit 16-1a + D3）：
> ```c
> export i8* uc_alloc(int n) {
>     int old_brk = uc_syscall(SYS_BRK, 0, 0, 0, 0, 0, 0);
>     int new_brk = old_brk + n;
>     uc_syscall(SYS_BRK, new_brk, 0, 0, 0, 0, 0);
>     return (i8*)old_brk;
> }
> ```
>
> **例 2**：`lib/print.uc::uc_print_str` 字符流输出（per 0.3.6 commit 16-1b）：
> ```c
> // digit-by-digit 写单字符（避免 i8[N] 数组）
> for (int i = 0; s[i] != 0; i++) {
>     char c = s[i];
>     uc_syscall(SYS_WRITE, 1, (int)(i8*)&c, 1, 0, 0, 0);
> }
> ```
>
> **理由**：用户核心论点 "库函数内部直接内联汇编即可" 在 0.3.6 验证成立 —
> `lib/memory.uc` / `lib/string.uc` / `lib/math.uc` 已直接 `uc_syscall`，
> 无需经 `sys::*` wrapper 间接层；0.3.4 commit 10e 已建立 `uc_syscall` primitive 路径。+ Cross-ref：preprocessor prefix 已统一为 # (per §10.2 unification, 0.3.6 S6 决策)。
```

**EN 版相同语义**（在 §10.4 末尾追加）：

```markdown
> **Note 1 (new in 0.3.6, G1 Interpretation B)**: The `sys::` namespace is preserved
> as a user-facing API. However, stdlib implementations under `lib/` **may directly
> invoke the `uc_syscall(SYS_xxx, ...)` low-level primitive** without routing through
> the `sys::*` wrapper layer. `uc_syscall` is defined in `lib/sys/raw.uc` (with inline
> assembly `asm { "syscall" }` for x86_64 / `asm { "svc #0" }` for aarch64 /
> `asm { "ecall" }` for riscv64, per §10.3 + §10.4.4).
>
> **When to use `sys::xxx` vs `uc_syscall`** (3 categories):
> - **User code**: prefer `sys::write(fd, buf, len)` (concise, cross-platform per §10.4.2 API)
> - **stdlib implementation (`lib/*.uc`)**: may bypass `sys::xxx` and call
>   `uc_syscall(SYS_xxx, arg1, ...)` directly to avoid wrapper indirection
> - **Systems programming** (e.g., `uc_syscall` itself): must use `uc_syscall` directly
>
> **Example 1**: `lib/alloc.uc::uc_alloc` (per 0.3.6 commit 16-1a + D3):
> ```c
> export i8* uc_alloc(int n) {
>     int old_brk = uc_syscall(SYS_BRK, 0, 0, 0, 0, 0, 0);
>     int new_brk = old_brk + n;
>     uc_syscall(SYS_BRK, new_brk, 0, 0, 0, 0, 0);
>     return (i8*)old_brk;
> }
> ```
>
> **Example 2**: `lib/print.uc::uc_print_str` (per 0.3.6 commit 16-1b):
> ```c
> // digit-by-digit single-char write (avoid i8[N] array)
> for (int i = 0; s[i] != 0; i++) {
>     char c = s[i];
>     uc_syscall(SYS_WRITE, 1, (int)(i8*)&c, 1, 0, 0, 0);
> }
> ```
>
> **Rationale**: The user's core argument ("library functions may use inline asm
> directly internally") is validated in 0.3.6 — `lib/memory.uc` / `lib/string.uc`
> / `lib/math.uc` already invoke `uc_syscall` directly; no need to route through
> the `sys::*` wrapper layer; 0.3.4 commit 10e established the `uc_syscall` primitive path. + Cross-ref: preprocessor prefix unified to # (per §10.2 unification, 0.3.6 S6 decision).
```

**背景**：0.3.6 S6 决策决定将 preprocessor directive prefix 从 `@` 统一为 `#`（方案 A）。原 0.3.3–0.3.5 spec 使用 `@`-prefix（`@ifdef`, `@if defined(...)`, `@include`, `@import`, `@modlaw` 等），0.3.6 起全 spec 统一为 `#`-prefix。本节详述 11 个 spec 改动 step（与 §5 Step 3.5 一一对应）。

**理由**（per S6 决策表）：
- **主因**：完整统一 0.3.6 编译期指令前缀，避免 `@`/`#` 双 prefix 长期共存造成 spec 读者认知负担
- **辅因 1**：§2.4 ASCII-only 后原 §10.2 第 (4) 条理由（"非 ASCII 友好"）已 stale
- **辅因 2**：与 C 生态工具链兼容 + 与 `#include`/`#import`/`#modlaw` 视觉对齐
- **辅因 3**：lexer 双 prefix 路径可简化（`scan_at_directive` 删除属 0.3.7+ 范围，本轮仅 spec 层面）

**Scope**：本轮**仅 spec 层面**。src-c/ lexer 端 `scan_at_directive` 删除属后续 0.3.7+ 范围（per Q13 决）。lib/ 内除 commit 16-7 (`lib/sys/raw.uc` `@ifdef` → `#ifdef`) 外**不动**其他 `@` 字符（per Q13 决）。

**11 个 step**（每 step = 1 spec 段落 / 表格行 verbatim 替换或新增）：

```

```

**§10.2 第一段新文**（Step 1 参考，实施 agent 必须读 0.3.5 spec §10.2 实际行文再 craft，**仅作语义参考**）：

> UltraCPP 采用 **C 风格的预编译宏语法**（`#` 前缀），不采用 Rust 的 `#[cfg(...)]` 风格。理由：与 C 生态工具链兼容；与 `src-c/` 现有的 C 实现无缝；学习曲线友好；与 `#include`/`#import`/`#modlaw` 视觉对齐。
>
> 注：`@`-prefix 形式曾在 0.3.3–0.3.5 使用，0.3.6 起统一为 `#`-prefix（per §10.2 unification, S6 决策）。

**EN 镜像**（Step 1 语义参考）：

> UltraCPP adopts **C-style preprocessor macro syntax** (`#` prefix), not Rust-style `#[cfg(...)]`. Rationale: compatibility with C ecosystem toolchain; seamless integration with existing C implementation in `src-c/`; friendly learning curve; visual alignment with `#include` / `#import` / `#modlaw`.
>
> Note: The `@`-prefix form was used in 0.3.3–0.3.5; from 0.3.6 onward it is unified to `#`-prefix (per §10.2 unification, S6 decision).
